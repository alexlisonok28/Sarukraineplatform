# Как читать код SAR Ukraine Platform

Этот файл предназначен для человека, который знаком с обычным JavaScript/HTML, но почти не работал с React.

## С чего начинать

1. `src/App.tsx` — главный компонент приложения. Здесь хранится текущая страница, состояние входа, профиль пользователя и переключение между экранами.
2. `src/components/Header.tsx` и `MobileMenu.tsx` — навигация.
3. `src/components/pages/*` — отдельные страницы сайта.
4. `src/utils/api.ts` — единая функция для запросов frontend → backend.
5. `src/utils/auth.ts` — хранение JWT-сессии и вход/выход.
6. `src/types.ts` — описание основных типов данных TypeScript.
7. `functions/api/[[path]].ts` — backend API для Cloudflare Pages Functions; он работает с Neon PostgreSQL.

## Базовые понятия React

### Компонент

Компонент — обычная функция, которая возвращает JSX (разметку, похожую на HTML).

```tsx
function Example() {
  return <div>Hello</div>;
}
```

### props

`props` — параметры компонента. Родитель передаёт данные дочернему компоненту.

```tsx
<Header isLoggedIn={true} />
```

Внутри Header значение можно получить через аргументы функции.

### useState

`useState` — память компонента.

```tsx
const [judges, setJudges] = useState([]);
```

- `judges` — текущее значение;
- `setJudges(...)` — изменить значение;
- после `setJudges` React автоматически перерисует нужную часть интерфейса.

### useEffect

`useEffect` запускает побочный код после отображения компонента. Чаще всего у нас он используется для загрузки данных с сервера.

```tsx
useEffect(() => {
  loadData();
}, []);
```

Пустой массив `[]` означает: запустить один раз при открытии страницы.

### Условный JSX

```tsx
{userProfile?.role === 'admin' && <Button>Редактировать</Button>}
```

Кнопка будет создана только для администратора.

Важно: это только интерфейсная проверка. Настоящая защита обязательно дублируется в backend API.

### map()

Массив данных часто превращается в список элементов интерфейса:

```tsx
{judges.map(judge => (
  <div key={judge.id}>{judge.name}</div>
))}
```

`key` помогает React понять, какой элемент списка изменился.

## Карта файлов

### `src/App.tsx`

Центр frontend-приложения. Здесь:
- определяется, какая страница открыта;
- проверяется локальная сессия;
- загружается профиль текущего пользователя;
- Header и страницы получают данные через props;
- выполняются переходы между страницами без полной перезагрузки браузера.

### `src/components/pages/CabinetPage.tsx`

Личный кабинет. Работа с профилем пользователя, его собаками и регистрациями.

### `src/components/pages/CompetitionsPage.tsx`

Список соревнований. Для обычного пользователя — просмотр/регистрация. Для `organizer` и `admin` появляются административные действия.

### `src/components/pages/ManageCompetitionPage.tsx`

Самая большая административная страница. Управление участниками, статусами и результатами конкретного соревнования.

### `src/components/pages/JudgesPage.tsx`

Публичный список судей. Добавление/редактирование/удаление доступно только `admin`.

### `src/components/pages/TeamsPage.tsx`

Список команд. Административные операции защищены ролью на backend.

### `src/components/pages/DocumentsPage.tsx`

Общие документы платформы. Метаданные документа хранятся в `app_data`, содержимое файла — в таблице `files` Neon.

### `src/components/pages/AdminPage.tsx`

Управление пользователями и их ролями. Страница доступна только администратору.

### `src/components/pages/RatingPage.tsx` и `ResultsPage.tsx`

Отображение результатов и рейтингов, полученных через API.

### `src/components/CompetitionModal.tsx` / `DogModal.tsx`

Формы в модальных окнах. Они собирают данные пользователя и возвращают их родительской странице через callback-функции.

### `src/components/ui/*`

Это низкоуровневые UI-компоненты (Button, Dialog, Select и т.п.), в основном библиотечный код. В бизнес-логике проекта их обычно менять не требуется, поэтому не стоит начинать изучение React с этой папки.

## Backend: `functions/api/[[path]].ts`

Cloudflare вызывает функцию для запросов `/api/*`.

Основной порядок обработки:

1. Получить `DATABASE_URL` и `JWT_SECRET` из Cloudflare Environment Variables.
2. Убедиться, что таблицы Neon существуют (`ensureSchema`).
3. По JWT определить текущего пользователя (`currentUser`).
4. Определить endpoint по URL и HTTP-методу.
5. Проверить авторизацию/роль.
6. Выполнить запрос в Neon.
7. Вернуть JSON frontend-приложению.

### Почему права проверяются два раза

Frontend скрывает кнопки, чтобы интерфейс был понятным. Но пользователь технически может вручную отправить HTTP-запрос. Поэтому backend снова проверяет роль через `requireRole`. Серверная проверка является настоящей защитой.

## Хранение данных

`users` — отдельная SQL-таблица пользователей и ролей.

`app_data` — key/value таблица JSONB. Например:
- `competitions` — список соревнований;
- `judges` — судьи;
- `teams` — команды;
- `profile:<userId>` — профиль пользователя;
- `dogs:<userId>` — собаки пользователя.

`files` — бинарные файлы документов.

## Важное правило при дальнейших изменениях

Если добавляется новая роль или меняются права, нужно проверить минимум четыре места:

1. SQL constraint в `users.role`;
2. backend `requireRole(...)`;
3. `src/types.ts` (`UserRole`);
4. UI: Header/AdminPage/соответствующая страница.

Иначе легко получить ситуацию, когда роль есть в базе, но frontend про неё не знает, либо кнопка скрыта, хотя API разрешает действие.
